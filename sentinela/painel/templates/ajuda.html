Gherkin (BDD) em português

Arquivos .feature também são roteiros. Converta um YAML com sentinela gherkin --roteiro x.yaml.

# language: pt
# alvo: http://127.0.0.1:8000
Funcionalidade: Login

  @CT01 @critica
  Cenário: Login com usuário válido
    Dado que eu acesso "/index.html"
    Quando eu preencho "rotulo=Usuário" com "qa"
    E eu clico em "Entrar"
    Então a URL deve conter "painel.html"
    E devo ver "Bem-vindo, qa!"

Frases aceitas: eu acesso “…”, eu faço login com “…” e “…”, eu preencho “…” com “…”, eu clico em “…”, eu aperto a tecla “…”, eu seleciono “…” em “…”, eu busco por “…”, eu espero “…” aparecer, eu envio GET “…”, devo ver “…”, não devo ver “…”, devo ver a mensagem de erro “…”, a URL deve conter “…”, o status deve ser 200, o campo JSON “…” deve ser “…”.

Se qualquer passo falhar, o caso fica REPROVADO, os passos seguintes não rodam e um defeito é aberto com a severidade do caso.

Como apontar para um elemento

Web

  • testid=login — data-testid (o mais estável)
  • rotulo=E-mail — pelo label do campo
  • papel=button:Entrar — papel de acessibilidade
  • #id, .classe, input[name=x] — CSS
  • texto=Esqueci a senha, placeholder=Buscar
  • Entrar — sem prefixo: tenta rótulo, botão, link e texto

Desktop

  • id=num7Button — AutomationId (o mais estável)
  • nome=Sete, tipo=Button;nome=Igual a
  • { x: 120, y: 300 } — coordenada (último recurso)

Massa de dados

  • {faker.name}, {faker.cpf}, {faker.email}, {faker.cellphone_number}
  • {env.SENHA} — do arquivo .env (segredos)
  • {dados.nome} — da seção dados: do roteiro

Exploração de validações

exploracao:
  preparar:
    - abrir: /cadastro
  campos:
    "#nome":  { tipo: nome }
    "#email": { tipo: email }
    "#cpf":   { tipo: cpf }
  enviar: Cadastrar
  sucesso_se: { url_contem: /ok }

Tipos: texto, nome, email, cpf, cep, telefone, numero, senha.
